# Запуск DiDi-shop

Инструкция для владельца магазина. Знать программирование не нужно: команды копируются целиком.
Время — около часа, из них 15 минут ждать сборки.

Что получится:

| Что | Где |
|---|---|
| Магазин в браузере (телефон и компьютер) | `https://<адрес>/` |
| Магазин на iPhone как приложение | Safari → `https://<адрес>/` → «На экран „Домой“» |
| Приложение для Android (APK) | ссылка из GitHub Releases, собирается автоматически |
| Панель администратора | `https://<адрес>/panel/` |
| Бэкапы базы и фото | каждую ночь, папка `backups` на сервере, хранятся 14 дней |

`<адрес>` — ваш домен или, пока домена нет, бесплатный адрес вида `203-0-113-7.sslip.io`
(это IP сервера через дефисы). HTTPS работает в обоих случаях.

---

## 1. Сервер (VPS)

Арендуйте VPS у российского хостинга: по закону 152-ФЗ данные покупателей из России
хранятся на серверах в России. Подойдут, например, Timeweb Cloud, Selectel, REG.RU, Beget.

Параметры при заказе:

- система **Ubuntu 24.04** (или 22.04, Debian 12);
- **2 ядра, 2–4 ГБ памяти, от 30 ГБ диска** (при 2 ГБ скрипт сам добавит файл подкачки);
- публичный IPv4-адрес.

После оплаты хостинг пришлёт **IP-адрес** и **пароль root**.

## 2. Домен (можно позже)

Без домена магазин работает на адресе `<IP>.sslip.io`, этого хватает для проверки и
тестовой оплаты. Перед подключением боевой ЮKassa домен понадобится (см. шаг 8).

Когда купите домен (например, `.ru` у REG.RU или Timeweb), у регистратора создайте
**A-запись**: имя `@` (или `shop`, если нужен поддомен), значение — IP сервера. Записи
обновляются от 15 минут до нескольких часов.

## 3. Запуск магазина

Подключитесь к серверу. На Windows откройте PowerShell, на Mac — «Терминал»:

```bash
ssh root@IP-СЕРВЕРА
```

(первый раз ответьте `yes`, затем введите пароль root — символы при вводе не видны).

Скачайте проект и создайте файл настроек:

```bash
apt-get update && apt-get install -y git nano
git clone https://github.com/Avtorhanov/ThreadsAndTrends-Django-Emporium.git didi-shop
cd didi-shop
cp .env.prod.example .env
nano .env
```

В редакторе заполните:

- `ADMIN_EMAIL=` — ваша почта, под ней вы будете входить в панель;
- `DOMAIN=` — домен, если он уже есть и A-запись настроена. Нет домена — оставьте пустым;
- остальное пока не трогайте.

Сохраните: `Ctrl+O`, `Enter`, выйти — `Ctrl+X`.

Запустите (одна команда — и для первого запуска, и для каждого обновления):

```bash
./deploy.sh
```

Скрипт сам установит Docker, сгенерирует секретные ключи и пароль базы, соберёт и запустит
магазин. Первый раз это занимает 10–15 минут. В конце он напечатает:

```
Готово.
  Магазин:                         https://203-0-113-7.sslip.io/
  Панель администратора:           https://203-0-113-7.sslip.io/panel/   (вход: you@example.ru)
  ...
  Пароль администратора: Dd…  (сохранён в .env как ADMIN_PASSWORD; после входа смените его в панели)
```

**Запишите адрес и пароль.**

## 4. Проверка

1. Откройте адрес магазина: это веб-витрина — каталог, поиск, фото товаров, покупка прямо
   в браузере. Это демо-товары, их можно удалить (шаг 10).
2. Зарегистрируйтесь как покупатель, положите товар в корзину, оформите заказ с оплатой
   «При получении».
3. Откройте `https://<адрес>/panel/`, войдите администратором: заказ виден в разделе «Заказы».
4. Нагрузочная проверка оформления (8 покупателей одновременно берут последние единицы товара):

   ```bash
   ./deploy.sh smoke
   ```

   В конце должно быть `SMOKE OK`. Тестовые заказы `smoke-…` отмените в панели.

## 5. iPhone

Отправьте покупателям адрес магазина. На iPhone: открыть в **Safari** → кнопка «Поделиться»
(квадрат со стрелкой) → **«На экран „Домой“»**. Появится иконка DiDi-shop, магазин открывается
как приложение, без адресной строки. Подсказку об этом покупатель видит в баннере сайта на iPhone.

## 6. Android (APK)

APK собирается на GitHub бесплатно. Адрес магазина зашивается в приложение при сборке,
поэтому сначала запустите сервер (шаг 3).

**Один раз — ключ подписи.** Им подписывается каждая версия: Android устанавливает обновление
только с тем же ключом. Файл ключа и пароль хранятся в надёжном месте (менеджер паролей).
Если ключ потерять, покупателям придётся удалить приложение и поставить заново.

В репозитории на GitHub: **Settings → Secrets and variables → Actions**.

- Вкладка **Secrets → New repository secret**, четыре секрета (значения — из файла
  `android-signing.txt`, который вам передали вместе с ключом `didi-shop-release.jks`):
  `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
- Вкладка **Variables → New repository variable**: имя `API_URL`, значение — адрес магазина
  целиком, например `https://203-0-113-7.sslip.io`.

**Сборка:** вкладка **Actions → Android APK → Run workflow → Run workflow**. Через 15–20 минут
APK появится в **Releases**, постоянная ссылка:

```
https://github.com/Avtorhanov/ThreadsAndTrends-Django-Emporium/releases/latest/download/didi-shop.apk
```

На главной магазина в браузере Android-покупатели видят ссылку «Скачать приложение для
Android» (адрес задан в `.env`, `ANDROID_APK_URL`).

Установка на телефоне: открыть ссылку → скачать → разрешить установку из браузера. Новая
версия — снова «Run workflow», ставится поверх старой.

Без секретов сборка тоже пройдёт, но APK будет подписан тестовым ключом (в сборке
предупреждение): годится, чтобы посмотреть самому, но не для раздачи покупателям.

## 7. Почта

Письма — коды восстановления пароля и уведомления о заказах. Пока почта не настроена, письма
не уходят, а печатаются в журнал (код сброса пароля можно найти так: `./deploy.sh logs worker`).

Подключите почтовый ящик домена (Яндекс 360, Mail.ru для бизнеса) или сервис рассылок
(Unisender Go): в `.env` заполните `EMAIL_HOST`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`,
`DEFAULT_FROM_EMAIL`, затем `./deploy.sh`.

## 8. ЮKassa (онлайн-оплата)

### 8.1 Тестовый магазин — без договора, деньги не списываются

1. Зарегистрируйтесь на [yookassa.ru](https://yookassa.ru) и создайте тестовый магазин:
   https://yookassa.ru/joinups?createTestShop=true (данные компании и договор не нужны).
2. В кабинете тестового магазина возьмите **shopId** и создайте **секретный ключ**
   (раздел «Интеграция → Ключи API»).
3. На сервере: `nano .env` и заполните

   ```
   ORDERS_ONLINE_PAYMENT_ENABLED=True
   YOOKASSA_SHOP_ID=<shopId>
   YOOKASSA_SECRET_KEY=<секретный ключ>
   ```

   затем `./deploy.sh`.
4. В кабинете ЮKassa: **Интеграция → HTTP-уведомления** — адрес
   `https://<адрес>/api/v1/payments/webhook/yookassa/` (`deploy.sh` печатает его в конце),
   отметьте события `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
5. Проверьте полный цикл: заказ с оплатой «Онлайн» → «Оплатить» → тестовая карта
   **5555 5555 5555 4477**, срок — любая будущая дата, CVC и код 3-D Secure — `123` →
   заказ стал «Оплачен» → отмените заказ → статус возврата «Деньги возвращены».
   Если заказ не стал «Оплачен» за минуту — `./deploy.sh logs app`.

### 8.2 Боевой магазин

1. Для договора ЮKassa проверяет сайт: нужен **домен** (шаг 2) и страницы с офертой,
   политикой обработки персональных данных, условиями доставки и возврата и контактами.
   Страницы уже есть (ссылки внизу сайта), но это **заготовки**:
   - в `.env` заполните реквизиты продавца `SELLER_NAME`, `SELLER_INN`, `SELLER_OGRN`,
     `SELLER_ADDRESS`, `SELLER_EMAIL`, `SELLER_PHONE` и выполните `./deploy.sh` — они появятся
     в подвале сайта и на страницах;
   - тексты покажите юристу: места для проверки помечены «[проверить юристу]». Файлы —
     `web/templates/web/legal/` (`offer.html` — оферта, `privacy.html` — политика ПДн,
     `delivery.html` — доставка и возврат); после правки — `./deploy.sh`. Пометку «Черновик»
     уберите в `web/templates/web/legal/_base.html`.
2. **Налоги и чеки 54-ФЗ сверьте с бухгалтером** и укажите в `.env`:
   `PAYMENTS_TAX_SYSTEM_CODE` (1 — ОСН, 2 — УСН доходы, 3 — УСН доходы минус расходы, 6 — патент),
   `PAYMENTS_VAT_CODE` (1 — без НДС). Самозанятым — `PAYMENTS_RECEIPTS_ENABLED=False`.
3. После подписания договора замените в `.env` ключи тестового магазина на боевые, `./deploy.sh`,
   и укажите тот же адрес HTTP-уведомлений в кабинете боевого магазина.

## 9. Переход на свой домен

1. A-запись домена → IP сервера (шаг 2), подождите, пока заработает.
2. На сервере: `nano .env` → `DOMAIN=ваш-домен.ru` → `./deploy.sh`.
3. Старый адрес `…sslip.io` продолжит работать: он зашит в уже установленные APK
   (`deploy.sh` запомнит его в `EXTRA_DOMAINS`).
4. Поменяйте переменную `API_URL` на GitHub и соберите новый APK (шаг 6).
5. Обновите адрес HTTP-уведомлений в ЮKassa.

## 10. Перед открытием для покупателей

- **Контакты.** В `.env` заполните ссылки для вкладки «Контакты» (сайт и приложение):
  `CONTACT_WHATSAPP` (номер), `CONTACT_TELEGRAM` (@имя или t.me/имя), `CONTACT_VK` (имя или
  vk.com/имя), при желании — подписи `CONTACT_*_NOTE`; телефон и почта берутся из `SELLER_PHONE` и
  `SELLER_EMAIL`. Затем `./deploy.sh`. Пустое значение — кнопка не показывается; опечатку
  `deploy.sh` покажет предупреждением `content.W001`.
- **Статьи.** В панели раздел «Статьи»: удалите три демо-статьи и напишите свои (заголовок,
  короткое описание, текст абзацами, до 6 фото, флажок «Опубликована»). Статьи сразу видны на
  сайте и в приложении и попадают в карту сайта для поисковиков.

- Сайт виден поисковикам: добавьте его в [Яндекс Вебмастер](https://webmaster.yandex.ru) и
  [Google Search Console](https://search.google.com/search-console), укажите карту сайта
  `https://<адрес>/sitemap.xml`. Делайте это уже со своим доменом (шаг 9).

- Удалите демо-товары в панели («Товары» → удалить) и поставьте в `.env` `SEED_DEMO=0`.
  Пока `SEED_DEMO=1`, при каждом `./deploy.sh` демо-товары восстанавливаются (демо-статьи —
  только пока в разделе «Статьи» пусто).
- Смените пароль администратора, если он генерировался.
- Укажите условия доставки: `PICKUP_ADDRESS` (адрес самовывоза, пусто — только курьер),
  `DELIVERY_COURIER_KOPECKS`, `DELIVERY_FREE_FROM_KOPECKS` (суммы в копейках: 500 ₽ = 50000).
- По желанию — мониторинг ошибок: проект Django на [sentry.io](https://sentry.io), DSN в
  `SENTRY_DSN`. Ошибки оплаты (неверная сумма, отказ в возврате) придут письмом.

## 11. Обслуживание

| Задача | Команда (в папке `didi-shop` на сервере) |
|---|---|
| Обновить магазин до новой версии | `git pull && ./deploy.sh` |
| Состояние сервисов | `./deploy.sh status` |
| Журналы | `./deploy.sh logs` (или `logs app`, `logs worker`, `logs caddy`) |
| Бэкап прямо сейчас | `./deploy.sh backup` |
| Восстановить из бэкапа | `./deploy.sh restore backups/db-….dump backups/media-….tar.gz` |
| Скачать бэкапы к себе (команда на своём компьютере) | `scp -r root@IP-СЕРВЕРА:didi-shop/backups ./didi-backups` |

Бэкапы лежат на том же сервере. Раз в неделю скачивайте их к себе или включите бэкапы
диска у хостинга: если сервер пропадёт, вместе с ним пропадут и бэкапы.

## 12. Магазины приложений (когда понадобится)

- **RuStore** — регистрация разработчика бесплатная, публикуется тот же APK (шаг 6).
- **Google Play** — взнос $25 (российские карты не принимаются), формат AAB вместо APK,
  тот же код.
- **App Store** — $99 в год и сборка на Mac. Пока её нет, iPhone-покупатели пользуются
  установкой с сайта (шаг 5).

Ни один из вариантов не требует изменений на сервере. Физические товары оплачиваются через
ЮKassa и в сторах, комиссия магазина приложений на них не распространяется.

## Если что-то не работает

| Симптом | Что сделать |
|---|---|
| `./deploy.sh` пишет «Сервисы не запустились» | Показан журнал. Частая причина — ошибка в `.env` (лишний пробел, кавычки). |
| Сайт не открывается по домену, по `sslip.io` открывается | A-запись ещё не обновилась или указывает не на тот IP. `./deploy.sh logs caddy` покажет попытки выпуска сертификата. |
| «Оплатить» нет в заказе | `ORDERS_ONLINE_PAYMENT_ENABLED=True` и ключи ЮKassa в `.env`, затем `./deploy.sh`. |
| Заказ оплачен, но статус не меняется | Проверьте адрес HTTP-уведомлений в ЮKassa. Без уведомлений статус всё равно сверится в течение 1–2 минут. |
| Не приходит код восстановления пароля | Почта не настроена (шаг 7), код — в `./deploy.sh logs worker`. |
| APK не ставится поверх старого | Другой ключ подписи — удалите старое приложение и поставьте новое. |
